# Model strategy

Use a provider-neutral registry with model id, capabilities, context, quantization, RAM/VRAM requirement, latency class, quality results, fallback, license and last validation. Do not freeze model names from planning documents. Benchmark coding, debugging, structured output, tool use, latency, memory and failure rate on the actual COMPUTE node before choosing defaults. Routing is admission-controlled and can degrade to queueing or a smaller validated model.
